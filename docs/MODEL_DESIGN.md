# Modeling and evaluation contract

IdentityGraph AI trains two binary targets. Takeover means an unauthorized actor in a
successful session. Identity risk means a fabricated claimed account identity at a
successful session assessment. Failed logins provide historical context but are not
scored by these classifiers. All results describe fictional simulated data.

## Baselines and deployment

Each target has four serving candidates: fixed rules, standardized logistic regression,
LightGBM using behavior, and LightGBM using behavior plus historical relationship
features. The feature names come from explicit allowlists in `features.py`. Raw entity
IDs, truth labels, scenario names, attack groups, and simulator metadata never enter a
model matrix. Additional no-device and no-assurance LightGBM ablations are excluded
from serving selection. Identity models fit the latest training assessment per account; session
models fit every eligible successful training session.

The rules use current device/region novelty, earlier failures, other accounts already
seen on a device, and previously observed shared identity attributes. Their coefficients
are fixed heuristics; calibration may adjust their raw scores using observed validation
labels. A shared IP alone does not contribute to the rule score. These are research
baselines, not externally validated security policies.

Training ends strictly before validation starts. The earlier half of validation's unique
timestamps fits Platt calibration. The later half selects the candidate with highest
average precision, with Brier score breaking a tie, and chooses its alert threshold.
These windows never share an event timestamp. Identity calibration and selection each
use the latest assessment per account within that window. If a calibration window has
fewer than 12 observations or only one label, calibration is skipped and reported.

Thresholds maximize validation recall subject to a 2% observed false-positive-rate
limit. This is an empirical validation constraint, not a guarantee on future data. With
too few benign examples it can effectively require zero false positives. A threshold
above 1 represents no alerts. No benign validation examples also disables alerts.
Validation performance used for selection is not an unbiased final estimate; held-out
test performance supplies that estimate. Test labels never fit a model, calibrator,
feature scaler, or threshold.

`bundle.joblib` contains every candidate and the selected estimator and threshold for
each target. The API uses only those selected baselines. `predict_baselines` produces
long-form evaluation rows with event_id, account_id, event_time, target, model, score,
threshold, label, and split. `selected_bundle_predictions` produces wide selected scores.
`model_metadata.json` records versions, features, calibration status and candidate
selection. Load joblib files only when generated by this trusted local project.

## GraphSAGE, RGCN and attention experiments

The graph experiment has two relation-specific GraphSAGE layers, each with 24 hidden
units and mean aggregation across relation types. It combines account, device, and IP
embeddings with the current query's standardized behavioral features. Separate small
heads predict takeover and fabricated-identity labels. It uses only numeric observable
node features. Node values receive a signed log transform; query scaling is fitted on
training examples only. Unknown graph nodes use a learned per-type fallback embedding.

Each query uses a snapshot at 00:00 UTC on its day. Snapshot edges come strictly before
that cutoff. This avoids future-edge leakage but makes graph context up to 24 hours
stale. The query's behavior features still use the exact historical event cutoff. An
account, device, or IP first seen during the same day can therefore use the missing-node
fallback until the next daily snapshot. This limitation is explicit in metadata.

Only training queries update GNN weights. Fixed epochs avoid validation-driven early
stopping; validation calibration and thresholds follow the same split as the baselines.
During later evaluation days, earlier observed validation and test events can enter
history without their labels. This evaluates online history accumulation rather than a
graph permanently frozen at the training boundary. Training snapshots never contain
future validation or test edges.

The identity loss uses inverse account-frequency weights within each daily batch.
Positive-class loss weights are derived from training labels and capped at 10. Both
heads share the graph encoder, so this comparison does not isolate task-sharing effects.
It also differs from the per-account baseline training sample; results should not be
presented as a controlled architectural comparison without acknowledging that difference.

The GNN saves `gnn_weights.pt`, `gnn_metadata.json`, and `gnn_predictions.csv`. Prediction
rows include both raw and calibrated target scores, fixed thresholds and split. It is
an offline experiment and does not replace the API model. An independently generated
shifted population uses its own observable graph inputs. Snapshot caches include the
population identity, preventing collisions between independently generated entity IDs.
All four encoders evaluate the shifted and both reserved populations without retraining.

RGCN applies two relation-aware layers to the flattened heterogeneous graph with eight
typed directed relations. GAT uses per-relation attention with per-node-type residual
projections. The relation-ablated RGCN assigns every edge one relation ID. This changes
both relation information and parameter count; it is not a capacity-matched ablation.
Each encoder retains the same query context, target heads and historical snapshot rules.
The final run trains each for 12 fixed epochs. Their output folders are `gnn/`,
`gnn_rgcn/`, `gnn_gat/` and `gnn_relation_ablated/`.

## Representations, relationships and anomaly scores

Node2Vec uses second-order random walks (p=1, q=2), skip-gram training with negative
sampling and 12-dimensional vectors. The graph freezes at day six. Only later training
queries fit its LightGBM readout; `lightgbm_matched_warmup` uses exactly the same rows
without embeddings. Unknown entities use zero vectors and explicit missing-node flags.
These transductive vectors do not carry entity identity into independently generated
populations. Raw entity IDs select rows but are not numerical classifier inputs.

The temporal link experiment predicts a first future account-device observation. Its
logistic decoder uses topology available at each window's start. Positive links involve
known endpoints; five window-specific negatives are sampled per positive. Train,
validation and test windows are separate, and thresholds use validation only. A link
that is not observed during a window is not confirmed absent forever. The result is
a sampled-pair ranking experiment with limited candidate coverage, not a fraud detector.

Isolation Forest fits training features without labels. Validation anomaly scores define
the percentile shown beside each stored assessment. It does not change either fraud
classifier's decision, and a percentile is not a probability of compromise.

Address-removal sensitivity recomputes historical features and runs the frozen baseline
models on future-time and cold-account subsets. Candidate sensitivity also compares exact
and fuzzy matching. Neither experiment refits or chooses models on the altered test data.

## Monitoring and outcome feedback

PSI summaries compare recent observed features and selected scores with frozen validation
histograms. The 0.2 threshold is descriptive. Nonempty windows with fewer than 100 current
observations are marked descriptive-only; missing distributions are marked insufficient.
Changes do not establish performance degradation. Submitted feedback
uses its own availability timestamp and never changes past scores. Reported performance
is conditional on which outcomes an investigator supplied; identity results retain the
latest eligible labeled assessment per account.

## Limits on claims

Risk scores are conditional on the simulator and its validation prevalence. They are
not calibrated probabilities for a bank, identity provider, or real population. A high
synthetic benchmark score can reflect simple generator rules. Report held-out attack
families, shifts, cold starts and legitimate sharing separately, including failed cases.
Per-account identity results and cluster candidate coverage are separate from session
classification. Successful implementation does not require the GNN to outperform the
tabular baselines.
